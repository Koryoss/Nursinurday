## 0. 베타 테스트의 목적 (연구계획서 핵심 가설 3가지)

| # | 가설 | 검증 질문 |
|---|---|---|
| H1 | 사용자는 자신의 상태를 지속적으로 기록할 수 있는가? | 기록이 지속되는가? (사용성 확보) |
| H2 | 개인 기준선 기반 시각화가 상태 인식을 돕는가? | 사용자가 자신의 상태 변화를 스스로 인식하게 되는가? |
| H3 | 이 정보가 생활을 스스로 조정하는 데 도움이 되는가? | 인식을 바탕으로 행동 변화가 나타나는가? (웰니스 플랫폼 효용) |

**원칙:** 앱 안에서 **자동으로 수집되는 데이터**와 **사용자가 직접 말해주는 피드백**을 분리한다.
"기록을 불편해했는가"는 로그로 알 수 없고, "기록에 몇 분 걸렸는가"는 설문으로 물을 필요가 없다.

## 1. 자동 수집 (로그 데이터) — 객관 지표

| 검증 항목 | 수집 방법 | 현재 구현 상태 |
|---|---|---|
| 매일 기록했는가? | 날짜별 기록 여부 (`daily_logs.log_date`) | ✅ Supabase 데이터로 산출 가능 |
| 기록 완료율 | 생성된 기록 수 / 전체 기간 | ✅ Supabase 데이터로 산출 가능 |
| 기록 시작~완료 시간 | `record_start`~`record_save` 이벤트 timestamp 차 | 🔶 코드 구현 완료 — 배포·DB 적용 시 수집 |
| 중간 이탈 여부 | `record_abandon` 이벤트 (저장 없이 화면 이탈) | 🔶 코드 구현 완료 — 배포·DB 적용 시 수집 |
| 수정 횟수 | edit 횟수 | ❌ 미구현 — 현재 기록은 insert-only 구조라 edit 자체 없음 |
| 가장 오래 머문 화면 | `screen_view` 이벤트 연속 간 timestamp 차 | 🔶 코드 구현 완료 — 배포·DB 적용 시 수집 |

> **현황 (7월 초):** 사용성 이벤트 로깅이 구현되었다. `usage_events` 테이블(마이그레이션 0006, RLS)과 `usageLog.ts` 모듈이 화면 진입(`screen_view`)·기록 시작(`record_start`)·저장(`record_save`, 소요시간·항목수 포함)·이탈(`record_abandon`)을 수집한다. **활성화 조건 2가지:** ① Supabase에 `0006_usage_events.sql` 적용, ② 로깅 포함 버전으로 앱 재빌드. 단, `record_start`는 "입력 시작"이 아니라 **기록 화면 진입** 기준이며, 수정 횟수는 기록이 insert-only라 측정 불가.

**결과 예시 (참여자 1인 기준):**

```text
7일 중 6일 기록 / 평균 기록 시간 2분 18초 / 평균 수정 횟수 1.4회
```

## 2. 짧은 인앱 설문 (주 1회)

매일 물으면 귀찮다. 7일마다 한 번.

**Q1. 이번 주 기록은 어땠나요?**

① 매우 쉬웠다 ② 쉬웠다 ③ 보통 ④ 어려웠다 ⑤ 매우 어려웠다

**Q2. 가장 불편했던 점은 무엇인가요?** (복수 선택)

- □ 시간이 오래 걸렸다
- □ 입력이 번거로웠다
- □ 무엇을 써야 할지 모르겠다
- □ 기록할 시간이 없었다
- □ 기록하는 걸 자주 잊었다
- □ 기타: ______

## 3. 베타 일지 (Beta Diary) — 주 1회, 2문항

참여자가 7~10명 규모에서는 숫자보다 짧은 메모가 더 가치 있다.

> **이번 주 CareFlow를 사용하면서 가장 도움이 되었던 순간은 언제였나요?**
>
> **이번 주 가장 불편하거나 아쉬웠던 점은 무엇이었나요?**

이 두 질문만 꾸준히 모아도 "기록이 귀찮다", "그래프가 이해되지 않는다", "아침 알림이 오면 기록하기 좋다" 같은 다음 개발 우선순위를 정할 질적 데이터가 쌓인다. 연구 활용 및 "사용자 실제 경험 기반 개선"의 근거 자료가 된다.

## 4. 베타 종료 인터뷰 (가장 중요)

원칙: **"기능"이 아니라 "경험"을 묻는다.** "효과가 있었나요?"가 아니라 "어떤 경험이 일어났나요?"를 확인한다.

### A. 기록 경험 (→ H1)

- 기록을 시작하게 된 계기가 있었나요?
- 기록하지 않은 날은 왜 기록하지 않았나요?
- 하루 중 언제 기록했나요?

### B. 사용성 (→ H1)

- 가장 마음에 들었던 화면은?
- 가장 불편했던 화면은?
- 기록하면서 헷갈린 부분은?

### C. 자기 인식 (→ H2, CareFlow의 핵심)

- 앱을 사용하면서 이전에는 몰랐던 내 패턴을 발견한 적이 있었나요?
- 기록을 하면서 스스로를 더 돌아보게 된 순간이 있었나요?
- 최근 일주일을 떠올리면, 내 상태를 이전보다 설명하기 쉬워졌나요?

### D. 행동 변화 (→ H3)

"앱이 바꿔줬나요?"라고 묻지 않는다. 대신:

- 기록을 하고 나서 하루를 보내는 방식이 달라진 적이 있었나요?
- 기록을 다시 읽어본 적이 있었나요?
- 다음 날을 계획할 때 앱을 참고한 적이 있었나요?

## 7. 베타 이후 마일스톤

| Milestone | 목적 (검증 가설) | 완료 조건 |
|---|---|---|
| **M1 – Closed Beta** | 사용자가 매일 기록할 수 있는가? (H1) | 회원가입·기록·조회·홈 요약·추세 그래프 안정화 |
| **M2 – Personal Baseline** | 개인 기준선이 사용자에게 이해되는가? (H2) | 기준선 계산·시각화 및 피드백 개선 |
| **M3 – Lifestyle Planning** | 생활을 스스로 조정하는 데 도움이 되는가? (H3) | 일정·환경 정보와 연계한 지원 기능 |
| **M4 – LinkNote Integration** | 기록과 지식을 자연스럽게 연결할 수 있는가? | LinkNote와 CareFlow의 맥락 연결 |

**버전 로드맵:** v0.8 Prototype → v0.9 Closed Beta → v1.0 Pilot → v1.1 Personal Baseline → v1.2 Lifestyle Planning
