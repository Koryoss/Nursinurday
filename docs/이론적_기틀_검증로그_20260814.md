# CareFlow 문헌고찰 — 이론적 기틀 대응관계 독립 검증 로그 (2026-08-14)

> **검증자 역할**: 작성자(정유진)와 별도 세션의 제2검토자. 목적은 동의 확인이 아니라 반박 지점 발굴. 저널 리뷰어/공모전 심사위원 관점에서 "이 매핑이 뚫릴 지점"을 찾는다.
> **검증 대상**: `8월 논문/CareFlow_문헌고찰_프로토콜.docx` "1-1. 이론적 기틀" 절(문단 6~10), `Nursinurday/Careflow/docs/SPEC.md`, `CareFlow_사회복귀지표_설계안.md`, `CareFlow_근거태깅_레지스트리.md`, 그리고 다른 세션이 이미 제안한 `논문_CareFlow_기여점_분석_0814.md`(§1, #18~20행) — 이 마지막 문서도 무비판적으로 수용하지 않고 동일한 기준으로 검증했다.
> **원저 확인 방법**: 웹 검색으로 1차 자료(원논문 본문·초록·직접 인용)를 직접 확인. 2차 요약·위키·플래시카드는 교차검증 보조 용도로만 사용했고, 표에는 원문 인용을 표기했다.

## 사전 확인 — 제품 문서 내부 근거 상태 (판정에 직접 영향을 준 사실)

`CareFlow_근거태깅_레지스트리.md` #12행은 "개인 7일 기준선 대비 band(낮음/보통/높음)"의 출처를 **"설계 정의(잠정)" · 근거강도 "약"**으로 명시하고 있고, `CareFlow_사회복귀지표_설계안.md` 본문(1절, 부록 F)에서 이 설계의 근거로 제시하는 것은 오직 **비의료기기 원칙("절대 임상 컷오프 회피")과 HRV/IMU 공학적 신호처리 로직**뿐이다. 두 제품 문서 어디에도 "Riegel"이라는 단어는 등장하지 않는다(`Riegel` 전체 검색 결과, 문헌군 안에서 `논문_CareFlow_기여점_분석_0814.md`에만 존재). 마찬가지로 근거태깅_레지스트리 #3행은 "전정질환 진료 92~99%가 외래(관리 공백)"의 출처를 **HIRA 통계**로 명시하고 있으며, Orem이나 자가간호결핍 개념은 인용하지 않는다. 즉 세 이론 모두 제품이 실제로 설계 시점에 참조한 근거가 아니라, **문헌고찰 작성 과정에서 사후적으로 덧붙여진 서사**라는 점이 아래 판정의 공통 배경이다. 이 자체가 틀렸다는 뜻은 아니지만("느슨한 이론적 정합성"과 "그 이론이 실제 설계를 이끌었다"는 서로 다른 주장이므로), 프로토콜의 서술이 후자로 읽히는 순간 과장이 된다.

## 추가 관찰 — `논문_CareFlow_기여점_분석_0814.md`(다른 세션 제안)에 대한 별도 코멘트

이 문서 §1(9~23행)은 위 세 주장을 그대로 다시 서술한 뒤, 근거태깅_레지스트리에 신규 #18~20행을 추가해 "근거강도 약 → 중"으로 격상시키자고 제안한다. 검증 결과 이 제안은 다음 이유로 그대로 채택하면 안 된다.

1. **순환 근거화**: #18~20행의 "출처"는 모두 이번에 검증한 세 이론이며, 세 이론 모두 원문을 직접 대조하면 CareFlow의 특정 설계 결정(4축 구성, 진료 사이 공백 정의, 상대 밴드 표시)을 직접 검증한 바 없다. 근거강도를 '중'으로 올리는 것은 실증적 근거가 늘어난 게 아니라, 서사적 정합성이 늘어난 것이다. '중'은 원래 "단일 연구·척도" 수준의 실증을 의미하는데(레지스트리 범례), 여기 세 이론은 CareFlow의 개입을 직접 검증한 단일 연구가 아니라 일반 이론적 틀이므로 '중' 격상 기준에 부합하지 않는다.
2. **③번 주장의 구성개념 불일치가 그대로 반복**됨 — 특히 #20행("증상 인지가 모니터링→관리를 매개(개인 기준선 표시 설계의 이론적 근거)")은 위 표의 [부정확] 판정이 그대로 적용된다.
3. 제안 자체가 "저자의 판단이 필요하다"고 명시하고 있어(§ 다음 행동 1) 자동 채택을 의도한 것은 아니지만, 논문의 서술을 그대로 제품 근거 문서에 옮기면 **논문의 과장이 제품 문서로 역류**하는 구조가 되므로 주의가 필요하다.

## 종합 권고

세 주장 모두 "완전히 틀린 인용"은 아니며, 방향성 자체(간호이론 프레임으로 재구성한다는 큰 그림)는 합리적이다. 그러나 세 건 모두 **원 이론의 하위구조를 생략하거나(①), 서로 다른 층위의 개념을 동일시하거나(②), 조작적 정의가 다른 결과를 특정 UI 설계의 직접 근거로 확장(③)**하는 공통 패턴을 보인다. 심사위원·리뷰어가 원문을 대조하면 "이론적 기틀"이 장식적 인용이라는 인상을 줄 위험이 크므로, 프로토콜 문단 8·문단 7·문단 9의 대응 표현을 위 "권장 대안 문장" 수준으로 완화하고, 세 이론이 실제로 무엇을 직접 검증했고 무엇을 검증하지 않았는지를 각주로 명시할 것을 권한다.
