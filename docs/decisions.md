# Architecture Decision Records (ADR)
CareFlow를 개발하면서 내린 주요 설계 결정과 그 이유를 기록합니다.
이 문서는 "무엇을 만들었는가"가 아니라 "왜 그렇게 만들었는가"를 기록하는 것을 목적으로 합니다.

---
## ADR-001 : CareFlow는 기록 중심 서비스로 설계한다.
Date 2026-07-03
Status Accepted
배경 많은 헬스케어 AI 서비스는 AI가 사용자의 건강을 분석하거나 상담하는 것을 중심으로 설계된다.
CareFlow는 의료기기가 아닌 자가관리 플랫폼을 목표로 하며, 사용자가 자신의 건강을 지속적으로 기록하고 이해하는 경험을 더 중요하게 생각한다.
결정 서비스의 중심은 AI가 아니라 Health Record로 정의한다. AI는 기록을 정리하고 구조화하는 보조 역할만 수행한다.
이유
- 의료적 판단과 명확히 구분하기 위함
- 장기적인 자기 이해를 지원하기 위함
- 서비스의 방향성을 일관되게 유지하기 위함

---
## ADR-002 : AI는 Assistant 구조를 사용한다.
Date 2026-07-03
Status Accepted
배경 AI가 하나의 거대한 모델에서 모든 기능을 수행하면 유지보수와 확장이 어려워진다.
결정 AI를 여러 개의 Assistant로 분리하고 AI Orchestrator가 이를 관리한다.
이유
- 기능별 책임을 분리하기 위함
- 새로운 기능을 쉽게 추가하기 위함
- 모델 교체를 쉽게 하기 위함

---
## ADR-003 : Study Workspace를 별도의 서비스로 유지한다.
Date 2026-07-03
Status Accepted
배경 CareFlow는 의료적 신뢰성을 지속적으로 확보해야 한다.
이를 위해 개발자가 의료·간호학 지식을 체계적으로 학습하고 관리할 공간이 필요하다.
결정 Study Workspace를 일반 사용자 기능이 아닌 내부 개발 환경으로 유지한다.
이유
- 의료 근거를 지속적으로 축적하기 위함
- LinkNote와 연계하기 위함
- 개발 과정 자체를 학습 과정으로 만들기 위함

## ADR-004 : LinkNote를 독립 프로젝트로 유지한다.
Date 2026-07-03
Status Accepted
배경 LinkNote는 CareFlow의 일부 기능이 아니라 장기적으로 발전할 독립적인 서비스이다.
결정 CareFlow와 연동하되 독립 저장소와 독립적인 개발 방향을 유지한다.
이유
- 간호학 학습 플랫폼으로 발전 가능
- 다른 프로젝트에서도 활용 가능
- CareFlow와 생명주기가 다르기 때문

---
## ADR-005 : 의료 근거는 참고 자료로만 활용한다.
Date 2026-07-03
Status Accepted
배경 CareFlow는 의료적 판단을 수행하지 않는다.
결정 Evidence는 AI의 판단 근거가 아니라 사용자가 참고할 수 있는 자료로만 제공한다.
이유
- 의료기기와 명확히 구분하기 위함
- 사용자의 자기 이해를 지원하기 위함
- 의료 전문가의 역할을 대체하지 않기 위함
